# 화면 제어 재발 원인 조사 인계

- 프로젝트 D:/Coding/ChronoLock. 요청: 재발 원인을 없애고 이전 작업 재개.
- 이번에는 멈췄던 화면 입력을 재호출하지 않고 설치 패키지와 IDE/Codex 로그를 읽기 전용으로 조사했다.
- 확인: @oai/sky 0.7.8의 sky.js는 nodeRepl.rpc("sky", execute 요청)를 기다린다. 래퍼 자체의 독립 취소/타이머는 보이지 않는다.
- 호스트 내부 근본 원인은 미확정이다. 파일 수정으로 해결했다고 보고하지 않는다.
- IDE 최근 6000줄 및 최신 Codex 로그 3개 끝부분을 확인했으나 입력 정지의 직접 오류는 못 찾았다.
- IDEA의 skipping attribution 메시지는 원인으로 단정하지 않는다.
- `docs/reports/computer-use-hang-20261021.md`에 재현·코드 경계·검증 한계·복구 조건 기록.
- AGENTS.md를 보완: REPL reset이나 창 조회 성공은 입력 복구 증거가 아니다. 호스트 재기동/수정과 입력·취소 검증을 구분한다.
- 문서 변경만 수행. 공식 패키지·보안/승인 설정·앱 코드 수정 및 프로세스 종료는 하지 않았다.
- 사용자에게 작업 저장 후 IDE와 Codex 앱 완전 종료·재실행을 요청할 상태다. 대화와 미저장 작업을 끊을 수 있어 자동 강제 종료는 하지 않았다.
- 호스트 재기동은 복구 시도이며 근본 해결 보장이 아니다. 재발하면 공급자 측 타임아웃/취소 경로 수정 필요.

## 이전 정지 및 승인
- 첫 호출은 get_window→Ctrl+N→list_windows 묶음, 약 102분 뒤 사용자 중단.
- 두 번째는 reset/import/list_windows/get_window 성공 뒤 단독 press_key에서 멈췄다.
- timeout_ms=15000 및 exec yield=1000을 지정했지만 wait(10000)이 약 178분 후 사용자 중단. 에이전트는 20초 취소 규칙을 실행할 제어권을 얻지 못했다.
- 새 창 입력 일부 실행 여부 및 잔류 요청 상태 불명. 동일 입력을 다시 보내지 않는다.
- 사용자 Chrome 창 조회/작업용 창 선택 승인은 유지. 다시 허가를 요구하지 않는다.
