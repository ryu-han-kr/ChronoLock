# ChronoLock 설정 문구 추가 작업 인계

- 프로젝트: `D:/Coding/ChronoLock`. 현재 사용자 요청은 에이전트 전용 설정에 한글 경로 관련 PowerShell 주의 문구 추가이며 완료했다.
- `AGENTS.md`에 `PowerShell 실행` 항목과 요청 문구를 그대로 추가했다.
- 첨부된 `.idea/.gitignore`는 확인했으며, 에이전트 지침은 루트 `AGENTS.md`에 기록했다.
- 검증: 변경 diff와 저장된 문구 확인. 문서 변경이므로 앱 테스트는 실행하지 않았다.
- 환경: `rg`가 PATH에 없어 PowerShell로 조회했다. 기본 `git status`는 dubious ownership으로 실패하여 명령 단위 safe.directory 옵션으로 확인했다. 전역 설정은 변경하지 않는다.
- 미커밋 변경: 이번 작업의 `AGENTS.md`와 이 인계 파일. 그 외 변경은 git status 결과를 참고한다.
- 이번 요청에 남은 작업은 없다. 아래 기존 미완료 항목은 사용자가 요청할 때 재개한다.
- 이전 작업: 접근성 시연 녹화, YouTube 일부 공개 업로드, Play 접근성 신고 저장 및 스토어 스크린샷 확보가 미완료다.
- release 0.2.0/versionCode 2, applicationId `com.chronolock.app`. 내부 테스트 출시됨. 비공개 트랙은 8명 임시저장 상태이며 12명 이상 14일 테스트 요건은 남아 있다.
- 개인정보 방침·데이터 보안·스토어 그래픽은 저장됨. 키 백업은 git 제외 `key-backup/`에 있지만 별도 디스크 백업은 미확인. 관리형 게시는 첫 검토 후 재시도 대상이다.
- 에뮬레이터는 `.tools/start-chronolock-emulator.cmd`의 ASCII SDK/AVD 환경을 사용한다. 현재 실행 상태는 재확인 필요. 로그 `.tools/emulator-demo-20261020.log`.
- ADB: `C:/Users/한경수/AppData/Local/Android/Sdk/platform-tools/adb.exe`. sandbox 계정 홈 경로 문제로 이전에는 실제 사용자 권한으로 실행했다.
- 시연 앱 사용 정보 접근과 Chrome 하루 1분 규칙은 검증됐지만 실제 차단 화면은 미확보다.
- `uiautomator dump`의 접근성 간섭이 의심되므로 촬영은 `.tools/demo-capture/screenshot.ps1` 및 이미지 확인을 사용한다. 원인은 미확정이다.
- 우선순위 1: 기기 부팅 확인 후 `/sdcard/chronolock-accessibility-final.mp4` 회수·검증, 고지/동의/접근성 활성화/규칙/차단 촬영. 진단용 `diagnostic-take.mp4`는 제출 금지.
- 녹화 명령: `adb -s emulator-5554 shell screenrecord --bit-rate 4000000 --time-limit 0 /sdcard/<고유이름>.mp4`. 종료 시 해당 PID에 `kill -2` 후 즉시 pull한다.
- 우선순위 2: 스토어 스크린샷 2~8장 확보·저장. 우선순위 3: YouTube 일부 공개 업로드 후 Play 접근성 신고 저장. 전체 출시/검토 전송은 별도 작업이다.
- 무관한 Chrome AWS 창 접근은 자동 승인 검토가 거절했으므로 재시도하지 않고 작업 전용 창을 사용한다.
