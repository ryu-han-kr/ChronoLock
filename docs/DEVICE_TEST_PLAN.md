# Android 기기 검증

아래 검사는 아직 실기기에서 실행하지 않았습니다. 결과에는 기기 모델, Android 버전,
APK 커밋, 배터리 설정, 실제 차단 지연과 관찰 내용을 기록합니다.

## 준비

1. Debug APK를 설치합니다.
2. 권한 안내에서 거절해도 앱을 둘러볼 수 있는지 확인합니다.
3. 안내에 동의한 뒤 사용 정보 접근과 ChronoLock 접근성 서비스를 켭니다.
4. 앱에서 감지 중 상태를 확인하고 테스트 앱을 선택합니다.
5. 각 독립 시나리오를 시작할 때 앱 설정에서 테스트 기록과 규칙을 초기화합니다.

## 필수 시나리오

| 검사 | 절차 | 기대 결과 |
|---|---|---|
| A: 일일 한도 | 하루 60초를 설정하고 대상 앱을 계속 사용 | 60초 도달 후 차단 화면 표시, 재진입도 차단 |
| B: 실행 횟수 | 3회 설정 후 앱과 홈 사이를 왕복 | 1~3회 허용, 4번째 진입 차단 |
| 중복 이벤트 | 3번째 허용 세션에서 앱 안의 화면을 여러 번 전환 | 횟수 증가나 차단 없음 |
| C: 쿨다운 | 30초 설정 후 앱 종료, 10초 뒤 재진입 | 남은 대기 표시, 종료 후 30초가 되면 허용 |
| 반복 재시도 | 쿨다운 중 홈과 앱 사이를 반복 이동 | 만료 시간이 뒤로 밀리지 않음 |
| 조합 | 하루 60초·3회·쿨다운 30초 함께 설정 | 적용되는 차단 사유로 차단 |
| 오프라인 | 비행기 모드에서 A/B/C 반복 | 차단 및 로컬 저장 정상 |
| 재시작 | 앱 UI 재시작, 접근성 재연결, 기기 재부팅을 각각 수행 | 저장한 규칙·카운터 유지, 복구 상태 확인 |
| 화면 잠금 | 대상 앱 사용 중 잠금 후 잠시 기다렸다 해제 | 잠긴 동안 사용량 증가 없음 |
| 자정 | 날짜 경계에서 사용 | 날짜별 사용량 분리, 일일 한도 초기화 |
| 설정 접근 | 차단 화면에서 홈·설정 이동 | 버튼 동작, 전화·시스템 설정 접근 가능 |
| 권한 해제 | 사용 정보·접근성 권한을 각각 해제 | 상태 안내, 해제 동작을 방해하지 않음 |
| 삭제 | 앱 내 모든 규칙·기록 삭제 | 차단 해제, 저장소 초기화 |

## 자동 저장소 테스트

기기를 연결하고 `android/`에서 `.\gradlew.bat :app:connectedDebugAndroidTest`를 실행합니다.
새 저장소 인스턴스의 카운터·쿨다운 복구, 파일 DB를 닫고 다시 연 뒤의 규칙·카운터 복구,
데이터 삭제를 검사합니다. 이 검사는 실제 접근성 차단 시나리오를 대신하지 않습니다.
