# ChronoLock 사용량 회복 후 재개 지침

프로젝트 `D:/Coding/ChronoLock`에서 이전에 승인된 미완료 작업을 이어서 진행해줘.
사용자는 2026-10-20에 사용량 제한 후 회복되면 이전 작업을 재개하도록 요청했다.

1. `AGENTS.md`를 따르고 `docs/handoff/YYYY-MM-DD-NNN.md` 중 날짜·번호가 최신인 파일 하나만 읽어라.
2. 최신 사용자 지시를 우선한다. 이미 완료한 검증이나 실패 원인이 바뀌지 않은 명령을 반복하지 마라.
3. 파일·기기·외부 서비스의 실제 상태를 먼저 확인하고, 마지막으로 검증된 지점부터 진행해라.
4. 남은 작업과 우선순위는 최신 인계의 "남은 일"을 따른다. (2026-10-20의 시연 영상·스크린샷·접근성 신고 작업은 0.9.0 출시로 끝났다. 2026-10-26 갱신)
5. 전체 출시·검토 전송, Play Console·개인정보처리방침 게시, 비용 발생, 무관한 계정 접근은 사용자 몫이다. 실행 환경의 승인 요구는 그대로 따른다.
6. 이번 실행의 변경·검증·남은 일은 AGENTS.md에 따라 인계에 기록한다. 완료됐으면 반복 작업을 하지 말고 완료 상태만 보고한다.
7. AGENTS.md의 `무응답·반복 즉시 중단` 규칙을 적용한다. 화면 제어는 짧은 yield와 명시적 timeout으로 한 단계씩 실행하고, 20초 무응답이면 취소 요청 후 해당 경로를 중단한다. 결과 불명인 입력은 재전송하지 않는다.

## 실제 예약 상태

- 2026-10-20: 재개 지침 저장 완료. 실제 자동 실행 예약은 등록되지 않았다.
- 현재 IDE 세션에 일반 작업 예약 도구가 노출되지 않았다. MD는 사용량 회복 감지나 실행 시작을 할 수 없다.
- 공식 문서상 IDE에는 Scheduled 관리 화면이 없다. 로컬 프로젝트 예약은 데스크톱 앱에서 설정하며 PC와 앱이 실행 중이어야 한다.
- “제한 발생 시점부터 5시간 후”를 자동 감지하는 트리거는 확인되지 않았다. 재개 시간은 서비스가 표시하는 실제 초기화 시간을 기준으로 설정한다.
- 예약 기능을 사용할 때 위 지침을 실행 프롬프트로 쓰고 프로젝트를 `D:/Coding/ChronoLock`으로 지정한다.
- 에뮬레이터와 현재 작업 파일이 필요한 작업이므로 해당 로컬 프로젝트에 접근할 수 있는 실행 환경이어야 한다.
