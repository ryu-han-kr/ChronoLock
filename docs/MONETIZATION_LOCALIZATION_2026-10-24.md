# ChronoLock 결제·무료/유료 구분·나라별 이름 조사 (2026-10-24)

`docs/GROWTH_AND_MONETIZATION.md`(10-23 초안)를 2026년 정책 변경에 맞춰 보완한다. 정책·요율은 2026-10-24에 확인한 공개 자료 기준이며,
**실제 적용 전에 Play Console 화면과 Google 공식 고객센터 문서로 다시 확인**한다(일부 수치는 언론 보도라 아래에 "보도"로 표시).

현재 코드 상태(확인함):
- `billing/PlayBilling.kt`: Play Billing 9.x. 구독 `AdFreeProduct`(광고 제거, SUBS)와 일회성 `ProProduct`(`chronolock_pro_lifetime`, INAPP)의
  조회·구매·acknowledge·대기(PENDING) 처리가 있음. 권한은 기기의 Play 구매 기록으로만 확인(서버 검증 없음).
- `feature/ProUi.kt`: 프로 카드 = 그룹 무제한, 사이트 50개, 목표 잠금·조각 비밀번호, 3개월 기록·1년 달력, 전체·나만의 테마.
  `PRO_GATING`(local.properties `chronolock.proGating`)이 false라 지금은 모두 열려 있음.
- `account/`: Supabase 인증 + Google 로그인 코드가 있음(웹 구매 연동 시 재사용 가능).
- `res/values/strings.xml`의 `app_name`은 `ChronoLock`, `translatable="false"`. 언어 폴더: values, -en, -es, -ja, -zh-rCN.

## 1. 결제 — 토스페이먼츠 웹 결제를 앱에 쓸 수 있나

### 1.1 결론 먼저
- **지금(2026-10) 앱 안에서 토스 결제창을 바로 띄워 프로를 파는 것은 불가.** Play 배포 앱의 디지털 기능은 Google Play 결제가 원칙이고,
  예외는 Google이 승인한 프로그램(한국 대체 결제 등)에 등록하고 API로 거래를 보고할 때뿐이다.
- **권장 경로: 1단계 Play 결제 일회성 "프로 평생 이용권"으로 출시 → 2단계(2027 이후, 매출이 생기면) 한국 새 결제 선택 제도에서 토스 웹 결제 검토.**
  소규모 매출에서는 토스 연동으로 아끼는 수수료(약 0~2%p)보다 개발·세무·환불·보고 부담이 크다.
- 토스페이먼츠는 **웹사이트 상품(앱과 무관한 상품)** 에 계속 쓰고, 앱 안에서는 웹 결제를 언급·링크하지 않는다(2단계 전까지).

### 1.2 Google Play 결제 정책 요점
- Play에서 받은 앱이 앱 안에서 디지털 상품(기능 잠금 해제, 테마·캐릭터, 광고 제거, 구독)을 팔면 Play 결제를 써야 한다.
  다른 결제 수단으로 **유도하는 문구·버튼·링크**도 금지(승인 프로그램 제외). [결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738)
- 다른 곳에서 이미 산 콘텐츠·권한을 앱에서 **이용만** 하게 하는 것은 허용(유도 없이). → 웹 구매 + 로그인 해제는 "앱 안 안내 없음"이 조건.
- 한국 거래는 지금도 Play가 판매자 역할을 맡아 부가세를 처리한다. 토스로 직접 팔면 **개발자가 판매자**가 되어 부가세 신고, 현금영수증,
  통신판매업 신고, 전자상거래법상 청약철회(7일) 고지·처리를 직접 해야 한다.

### 1.3 한국 대체 결제 프로그램(현행, 2026-12 말까지)
[South Korea alternative billing](https://support.google.com/googleplay/android-developer/answer/11222040) 기준:
1. 대상: 한국의 휴대전화·태블릿 사용자에게 대체 결제를 제공하는 앱.
2. 등록: Play Console → 설정 → **대체 결제(Alternative billing)** → 약관 동의, 결제 프로필 설정.
3. 신뢰·안전: **PCI DSS 준수 인증**, 사용자가 사기 거래를 신고할 수단 제공.
4. Play Billing Library의 대체 결제 API 연동(앱별로 사용 여부·결제수단 로고·구독 관리 URL 설정).
5. 승인된 한국 거래를 **결제 승인 후 24시간 안에 API로 Google에 보고**(2023-08 이후 수동 보고 불가).
6. Google이 청구하는 조정 수수료 납부: Play 수수료에서 **4%p 인하**(보도·발표 기준 15% 등급 → 11%).
- 선택 화면은 Google이 그린다(직접 만들지 않음). 결제 수단별로 다른 가격 허용. 앱 안에서 대체 결제 홍보 가능.
- **웹 링크 결제도 이 프로그램 안에서 허용**: 한국 사용자에게 웹 결제로 연결 가능하나 **앱 내 임베디드 WebView로 열어야** 하고,
  같은 연동·보고·UX 요구사항과 4%p 인하가 적용된다.
- [사용자 선택 결제(User choice billing)](https://support.google.com/googleplay/android-developer/answer/13821247): Play 결제와 개발자 결제를
  나란히 보여 주는 방식. 한국에서는 위 프로그램 안의 선택지로 운영된다(Play 결제를 함께 보여 주는 형태).
- 소규모 개발자는 별도로 **15% 수수료 등급(연 100만 달러 이하)** 을 Play Console에서 신청해야 15%가 적용된다(미신청 시 30%).

### 1.4 2026년 개편(보도) — 한국은 2026-12-31까지 시행 예정
- 2026-06-24 발표, 6/30 미국·영국·EEA 시작, 9/30 호주, **한국·일본 12/31까지**, 그 외 2027-09-30.
  [디지털데일리 8/11](https://www.ddaily.co.kr/page/view/2026081116525803692), [다음뉴스 6/29](https://v.daum.net/v/20260629170503806),
  [Android Authority](https://androidauthority.com/google-play-billing-changes-3681025), [ppc.land](https://ppc.land/google-play-developers-face-25-percent-fee-under-new-structure/)
- 구조: **서비스 수수료**(결제 수단 무관) 연 100만 달러까지 10%, 구독 10%, 초과분 일반 인앱 20% + **결제 수수료** Play 결제 사용 시 5%.
  대체 결제·외부 웹 링크는 결제 수수료 없음(대신 PG 수수료는 개발자 부담). 외부 링크도 PCI DSS·자녀 보호 등 안전 기준 적용.
- 소규모 앱 실효 비교(9,900원 판매 가정, PG 수수료는 토스 계약 요율로 재확인):

| 시기 | Play 결제 | 토스(대체/웹) | 차이 |
|---|---|---|---|
| 현행(15% 등급) | 15% | 11% + PG 약 3% ≈ 14% | 약 1%p |
| 개편 후 | 10% + 5% = 15% | 10% + PG 약 3% ≈ 13% | 약 2%p |

→ 9,900원 1건당 100~200원 차이. 월 수백 건 이하라면 연동 비용이 더 크다. **개편안 공식 문서가 한국에 게시되면 다시 판단.**

### 1.5 토스페이먼츠가 맞는가
- 가능성: 대체 결제·외부 링크 제공자는 "개발자가 고른 PSP"면 되므로 토스도 원칙상 가능. 다만 현재 설정은 **웹 일회성 결제만**이므로
  구독은 불가, **일회성 프로 이용권**만 맞다.
- 확인할 것: ① 토스페이먼츠의 PCI DSS 인증서·SAQ 범위(개발자 인증 근거) ② WebView 결제창 지원(앱스킴·카드사 앱 전환 처리)
  ③ 결제 완료 웹훅 ④ 환불 API(Google 보고와 맞추기) ⑤ 사업자 정산·부가세.

### 1.6 웹 구매 + 앱 로그인 해제 방식
- 흐름: 웹(토스) 결제 → 토스 웹훅 → Supabase `entitlements(user_id, product, source, purchased_at, refunded_at)` 기록
  → 앱에서 Supabase 로그인(Google) → 권한 조회 → 프로 해제.
- 정책: 2단계 전에는 앱 안에 "웹에서 사면 싸요/웹에서 구매" 같은 안내·링크를 두지 않는다. 앱 밖(웹사이트, SNS)에서만 홍보.
- 영향: 로그인·서버 재가동 → 개인정보처리방침과 Play **데이터 보안** 신고를 "수집 있음(계정·구매 기록)"으로 수정.
  "모든 데이터는 기기에만"이라는 현재 등록정보 문구도 고쳐야 한다.
- 위험: 앱 안 유도 적발 시 업데이트 거절·앱 삭제, 환불 분쟁 이중 처리, 로그인 없는 사용자 경험 악화, 오프라인 권한 캐시 위변조.

### 1.7 권장 단계와 필요한 작업
**1단계 — Play 결제 일회성 프로(바로 진행)**
1. 통신판매업 신고 완료 → Play Console **결제 프로필**에 사업자 정보·정산 계좌 → **15% 수수료 등급** 신청.
2. 수익 창출 → 인앱 상품 `chronolock_pro_lifetime` 등록·가격(아래 2.3)·활성화. 라이선스 테스터에 본인 계정.
3. `chronolock.proGating=true`로 내부 테스트 → 구매·복원·다른 기기·환불(Play Console 환불 후 권한 회수) 확인.
4. 기존 비공개 테스터에게 **프로모션 코드** 지급(무료 → 유료 전환 반발 방지).
- 코드 변경(작게):
  - 프로 구매 시 광고 제거도 포함(`AdFreeProduct.entitled || ProProduct.entitled`). 광고 제거 구독은 신규 판매 중단 또는 유지 결정.
  - `BillingFlowParams.setObfuscatedAccountId(해시된 Supabase user id)` — 나중에 웹/앱 권한 통합 시 연결 키(로그인 시에만).
  - 환불·취소 반영: 앱 시작 시 `queryPurchasesAsync` 재확인(이미 있음) + 필요하면 Voided Purchases API를 Supabase Edge Function에서 조회.
  - 캐릭터·테마 게이트를 `ProGate` 한 곳에서 판단(기능별 상수 표 2.1 반영). 프로 카드 문구에 캐릭터·움직이는 테마 추가(5개 언어).

**2단계 — 토스 웹 결제(2027 상반기 이후 재검토)**
- 조건: 한국 개편 공식 문서 확인 + 월 매출이 연동 비용을 넘을 때.
- 작업: Play Console 대체 결제/외부 링크 등록 → `BillingClient`의 대체 결제(또는 외부 링크) 프로그램 활성화와 Google 선택 화면 표시
  → 임베디드 WebView 결제 화면 → 토스 웹훅 → Supabase 권한 + **24시간 안 Google 거래 보고**(Play Developer API `externaltransactions`)
  → 환불 시 보고 갱신 → 데이터 보안·개인정보처리방침 수정.
- 한국 외 국가는 Play 결제만 유지(미국 외부 링크 등은 별도 프로그램이라 범위 밖).

## 2. 무료 / 프로 구분 제안

### 2.1 원칙
- **핵심 가치(앱 제한 + 크롬 사이트 차단 + 엄격·잠금으로 못 풀게 하기)는 무료로 끝까지 작동**해야 리뷰가 지켜진다.
- 프로는 "더 많이·더 길게·더 예쁘게": 개수 한도, 장기 기록, 꾸미기(캐릭터·테마). 데이터 안전(백업)은 무료.
- 이미 쓰는 기능이 업데이트로 막히지 않게: 한도를 넘는 기존 설정은 **유지하되 새로 추가만 막는다**.

| 기능 | 무료 | 프로 |
|---|---|---|
| 앱 제한(하루·1회·횟수·대기·예약) | 무제한 앱 | 동일 |
| 집중 모드·빠른 설정 타일 | ✔ | ✔ |
| 엄격 모드(완화 지연) | ✔ (최대 1시간) | ✔ + 지연 길이 확장(예 24시간) |
| 잠금 모드 | 기간 잠금 | + 목표 잠금·조각 비밀번호 |
| 앱 그룹 | 2개 | 무제한 |
| 웹사이트 차단 | 5개 | 50개 |
| 기록 | 30일 + 주간 요약 | 90일 앱별 + 1년 달력·연간 통계 |
| 백업·복원(파일) | ✔ | ✔ |
| 캐릭터(수달·흰너구리·햄스터·토끼·북극여우) | 1마리 선택 + 기본 포즈 3개 | 5마리 전체 + 포즈 10개 |
| 테마 | 기본 5개 + 색상 휠(정지 테마) | 움직이는 테마·효과 조합·전체 갤러리 |
| 광고(켜는 경우) | 배너 | 없음 |

- 현재 코드 한도(그룹 1·사이트 3)보다 조금 넉넉하게 제안: 경쟁 앱 무료 한도(AppBlock 안드로이드 일정 3개×앱 5개 수준)와 비슷하게 맞춤.
- 캐릭터는 "수집" 동기가 강해 유료 전환에 유리하나, **첫 캐릭터 선택은 무료**로 해 정이 들게 한다. 나중에 캐릭터 개별 판매(소액 인앱)도 가능.

## 3. 나라·언어별 앱 이름

### 3.1 방법
1. **언어별 스토어 제목**: Play Console → 스토어 등록정보 → 기본 등록정보 → 번역 관리 → 직접 번역 추가. 기기 언어별로 제목(30자)·간단한 설명(80자)·
   자세한 설명(4000자)이 바뀐다. 가장 쉬운 기본 방법.
2. **국가별 맞춤 스토어 등록정보(custom store listing)**: 앱 이름·아이콘·설명·그래픽을 국가(또는 유입 URL·키워드 등)별로 다르게. 최대 50개,
   한 국가는 한 맞춤 등록정보에만 지정, 번역을 따로 넣지 않으면 기본 언어로 노출.
   [Google 도움말](https://support.google.com/googleplay/android-developer/answer/9156429) · [소개](https://play.google.com/intl/en-GB_ALL/console/about/customstorelistings)
   → 예: 스페인(es-ES)과 중남미(es-419)를 다른 제목으로, 대만·홍콩은 번체 등록정보.
3. **기기 아이콘 아래 이름(런처 라벨)**: `res/values-xx/strings.xml`의 `app_name`. 현재 `translatable="false"` 단일값.
   언어별로 바꾸려면 `values/strings.xml`의 `translatable="false"`를 빼고 `values-ja` 등에 `app_name`을 넣는다.
   **권장: 런처 이름은 모든 언어에서 `ChronoLock` 유지**(짧아야 잘리지 않고, 접근성 서비스·알림·설정 화면에 같은 이름이 보여 신뢰에 유리).
   필요하면 일본만 `クロノロック`처럼 음역 검토(현지 검색엔 스토어 제목이 더 중요).

### 3.2 언어별 제안(글자 수 확인함)

### 3.3 중국어 주의
- Google Play는 **중국 본토에서 서비스되지 않는다**. zh-CN 등록정보는 싱가포르·말레이시아 등 간체 사용자와 해외 중국어 사용자용.
  본토 출시는 별도 앱마켓(화웨이·샤오미 등)·소프트웨어 저작권 등록 등이 필요해 범위 밖.
- 대만·홍콩은 번체(zh-TW/zh-HK)를 쓰므로, 수요가 보이면 번체 번역(`应用`→`應用`, `拦截`→`攔截`)을 맞춤 등록정보로 추가.

### 3.4 상표·브랜드 일관성 주의
- [메타데이터 정책](https://support.google.com/googleplay/android-developer/answer/9898842): 제목에 이모지·전부 대문자·"최고/1위/무료" 같은 홍보 문구·
  키워드 나열·다른 앱 이름 금지. 경쟁사·플랫폼 상표(YouTube, Instagram, Chrome)는 **제목에 넣지 말고** 설명에서 기능 설명으로만 사용.
- 모든 로캘에서 `ChronoLock`을 제목 맨 앞에 같은 표기로 유지(검색·리뷰·스크린샷 일관성). 번역 제목이 브랜드처럼 보이지 않게 구분자(` - `, `: `) 사용.
- "ChronoLock"과 비슷한 이름의 기존 앱·상표가 있는지 KIPRIS(한국), USPTO, EUIPO, J-PlatPat에서 9류(소프트웨어)·42류 검색 후,
  사업자 등록 뒤 한국 상표 출원을 검토. 캐릭터 이름·그림도 같은 방식으로 보호 검토.
- 런처 이름을 언어별로 바꾸면 사용자가 접근성 설정에서 앱을 못 찾을 수 있다 → 런처 이름은 하나로 유지.
