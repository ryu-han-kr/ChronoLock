## 회원(로그인)·배너 광고 추가 (2026-10-18)

  설정에 계정 카드(선택 로그인·로그아웃·계정 삭제 확인). 규칙·사용 기록은 계속 기기에만 있습니다.

  Debug는 Google 테스트 단위, Release는 키가 없으면 광고 없음. 광고 제거는 "준비 중" 표시(`AdFreeEntitlement` 항상 false).
- WorkManager(광고 SDK 의존) 작업 ID 범위를 1000~100000으로 지정해 HistoryJobService(301)와 충돌을 막았습니다.
- 검증: 단위 85개 통과, Lint 오류 0(새로 보인 GradleDependency 경고는 최신 버전 안내), 계측 50개 통과

## 오류 사전 점검 및 수정 (2026-10-13)

- 1회 사용 한도 도달 후 active 세션이 없어지면서 다음 tick에서 차단이 풀리는 도메인 오류를 수정했습니다.
  차단 중에는 종료된 세션의 사용량을 유지하고, 앱을 떠나거나 제한을 변경·삭제하면 해제합니다.
- 저장된 활성 앱과 현재 앱이 같아도 재부팅 전 세션을 이어 쓰지 않도록 했습니다.
  boot ID와 경과 시간을 확인하고 새 진입에 실행 횟수·쿨다운을 적용합니다.
- 비활성화한 규칙의 사용량을 복구에서 제외하고 음수 복구 값이 기존 사용량을 줄이지 않도록 했습니다.
- 복구한 일일 사용량이 한도에 도달했다면 복구 결과에서 즉시 차단하고 저장하도록 했습니다.
- 복구 판정을 UsageMonitor.restore로 이동하고 LocalRepository가 해당 로직을 호출하게 했습니다.

검증: 기존 로직에서 신규 재현 테스트 4개 실패를 확인한 후 수정했습니다.
도메인 회귀 테스트 9개를 추가했고 전체 **41개 통과**(RuleEngine 18, UsageMonitor 23)를 확인했습니다.
명령: `android/gradlew.bat -g D:/Coding/ChronoLock/.tools/gradle-home -PdomainOnly :domain:test --offline --console=plain`.
Room 복구 통합 테스트 2개도 추가했지만 이번 환경에서 실행하지 못했습니다.

이번 변경의 APK 빌드·Lint는 **Android SDK 경로/설치 부재로 미완료**입니다.
로컬 Android 설정 경로 오류는 작업용 ANDROID_USER_HOME 지정으로 해소했으나 이후 SDK 탐색에서 중단됐습니다.
IDE 디버거는 해당 테스트의 실행 구성을 생성하지 못해 사용하지 못했고 Gradle 재현 테스트로 검증했습니다.
디버거 점검에 추가한 로그포인트는 제거했습니다. 실기기 설치·검증 및 새 APK 배포는 하지 않았습니다.

남은 검증: SDK 준비 후 APK/Lint 및 Room 테스트 6개 실행, 실제 재부팅·잠금·접근성 재연결 검사.
1회 사용 한도는 아직 도메인 전용 기능입니다. 차단 중 세션 상태는 메모리에 유지하며,
해당 기능을 제품에 연결할 때 저장 스키마 및 서비스 재시작 복구까지 확장해야 합니다.
서비스 중단 중 실행 횟수·이전 날짜 사용량 복구의 기존 제한도 남아 있습니다.

## 기존 구현의 명세 차이와 남은 제한

- 임시 제품명 FocusGuard 대신 ChronoLock 및 `com.chronolock`을 사용합니다.
- PoC는 앱별 한 개의 규칙 집합을 저장합니다. UUID를 갖는 개별 BlockingRule,
  모드 및 전체 이벤트/세션 테이블은 아직 구현하지 않았습니다.
- 설정 단위는 초지만 측정값·체크포인트는 밀리초입니다. 명세 5장의 전체 초 저장 모델과 차이가 있습니다.
- 재시작 복구는 오늘의 미관측 사용시간을 보완하지만 미관측 실행 횟수는 보완하지 않습니다.
- 분할 화면/PiP, 제조사별 서비스 종료, 실제 오버레이 안전 접근은 미검증입니다.
